1. Introduction
เอกสารนี้อธิบายข้อกำหนดของ AI harness — สถาปัตยกรรมที่เชื่อม context หรือข้อมูลประกอบการทำงานระหว่างระบบ
อย่างควบคุม — และ Software Factory ซึ่งเป็นการนำสถาปัตยกรรมนี้ไปใช้สร้างซอฟต์แวร์จากข้อกำหนด

3. Functional Requirements
ระดับ Harness (สถาปัตยกรรม)

   ID                  ข้อกำหนด

   HR-01               ต้องมี workspace สำหรับโค้ด ข้อกำหนด และ version control

   HR-02               การเข้าถึงระบบภายนอกต้องผ่าน connector/app ที่ใช้ least-privilege permissions

   HR-03               ต้องรองรับการตั้งค่า agent workflow (agent เดี่ยวหรือหลายตัว)

   HR-04               ต้องนิยามสัญญา input/output ของแต่ละ capability ได้

   HR-05               ต้องแยกปรับการรันงาน การตรวจสอบผล และต้นทุนได้


ระดับ Software Factory (instance)

   ID             ข้อกำหนด

   FR-01          รับคำขอจาก GitHub Issue พร้อม acceptance criteria

   FR-02          ให้ bot ตัวแทน harness รายงานขั้นตอนผ่าน Issue comments: จัดประเภท → วางแผน → พัฒนา → ตรวจทาน

   FR-03          ให้ Software Factory bot สร้าง branch, commit และเปิดหรือจัดการ draft PR

   FR-04          ส่งมอบโค้ด ทดสอบ และเอกสารตามเกณฑ์ใน Issue

   FR-05          มี independent review หรือการตรวจทานอิสระก่อนเปิด PR

   FR-06          สัญญาผลลัพธ์สิ้นสุดที่ draft PR — ไม่รวม merge/deploy (โดยออกแบบ)

   FR-07          เก็บกวาดหรือปิดบริการที่มีค่าใช้จ่ายทั้งหมดเมื่อ Software Factory ทำงานเสร็จ


FR-07 เป็นข้อกำหนดเมื่อจบงาน ไม่ใช่ผลที่สาธิตแล้ว: รอบอ้างอิงยังปล่อย sandbox จนหมดเวลา ดูข้อจำกัดและต้นทุนใน
เอกสารออกแบบ


4. Nonfunctional Requirements

   ID                 ข้อกำหนด

   NFR-01             แพ็กเกจผลลัพธ์ต้องไม่พึ่งพา library ภายนอกขณะรัน เมื่อ Issue กำหนดให้ใช้เฉพาะ standard library

   NFR-02             CI ผ่านตามชุดสภาพแวดล้อมทดสอบที่กำหนด

   NFR-03             ตรวจสอบย้อนกลับได้ด้วย GitHub links

   NFR-04             ต้นทุนต่อรอบวัดได้และใช้เป็นจุดอ้างอิง

5. Acceptance Criteria

   ID                         เกณฑ์ระดับระบบ

   AC-01                      มี Issue เป็น input และ draft PR เป็น output ที่เชื่อมกัน

   AC-02                      มีประวัติขั้นตอน Factory บน Issue

   AC-03                      CI ของ PR ผ่าน

   AC-04                      การตรวจทานอิสระไม่เหลือประเด็นที่ขัดขวางการส่งงาน

   AC-05                      Output เป็น draft PR สำหรับ human review

   AC-06                      มีตัวเลขต้นทุนอ้างอิงของรอบที่สำเร็จ


การผ่าน AC หมายถึงได้ draft PR ที่พร้อมตรวจทานและผ่าน CI — การ merge/deploy เป็นการตัดสินใจของมนุษย์นอก
ขอบเขต Factory ส่วน multi-agent ระดับองค์กรเป็นทิศทางการศึกษา
